## 3. 连接与安全边界

- 重新向用户获取有效跳板/局域网入口及凭据；动态 tmate 邀请和密码不入库。
  旧邀请不能假定仍有效。普通交互 SSH/telnet 即可，不需要旧会话的 Python
  终端助手。同一共享终端不能由两个操作者并发输入。
- 主猫：H3C HM2004-DU，测试时 `192.168.1.1`，SSH 用户 root；
  测试时无密码，下一次须复核。已知 SSH 指纹为
  `SHA256:yFchZef1qbrYbsTkvwtyxw+N9unnmhxvn7UIHaTprJQ`；
  若不同先向用户确认，不盲目接受。
- 当前子猫 TEWA：测试时 `192.168.1.100`，telnet；认证由用户提供。
  登录后用户提供的维护方式是单独输入 `;`，语法报错不代表失败。
  必须通过 `/proc/self/status` 等验证权限，不凭 `$` 提示符判断。
- F650A 曾使用相同地址，但目前已被替换。先核对型号/固件/光 SN，
  不要把 TEWA 的命令发给 F650A，或把跳板/主猫 shell 当作子猫。
- TEWA BusyBox 缺少常见 applet：`id`、`printf`、`head` 等可能不存在。
  优先 `cat`、`tail`、`grep -m`；命令失败必须保留错误。
- 硬件 ONU-ID、接口、进程 PID 和作业 ID 都是现场分配值，不写死复用。
  不删除 `/tmp/fttr-onu-*.lock` 或 `/tmp/fttr-hardware.lock`；
  不绕过正常控制器/库存作业的资源锁。

### 首轮只读检查

主猫：

```sh
fttrctl status --json
sha256sum /usr/bin/fttrd /usr/bin/fttrctl
ip addr show br-tr069
ip link show fttr1
ss -lnt
```

先从状态确认实际接口，再查对应接口；`fttr1` 只是当时 ONU 0 的结果。
若 `ss` 不存在，使用系统已有的监听查询工具，不因此判断 ACS 未监听。
`ubus call fttr status` 已实测返回 Method not found，正式状态入口是
`fttrctl status --json`。完整状态和配置可能含敏感字段，原始输出不要入库。

TEWA 子猫：

```sh
cat /proc/self/status
bs /Driver/pOn_stack/ gi
bs /Driver/pOn_stack/ ptcnt
bs /Bdmf/ Objects gem
/sbin/ifconfig veip0.1
```

先发现对象和映射，再执行型号文档里的 `Examine` 命令。

## 6. 在新机器重建原厂静态分析

固定来源及已核对结论见
[TEWA 原厂备份交叉核对](scty-tewa-768g.md#原厂备份交叉核对)。
不需要旧会话里的固件解包目录；只下载 `mtd3.bin.gz` 即可恢复本轮
主要证据。不要下载/打印配置、工厂或客户数据分区作为默认调查步骤。

```sh
mkdir stock-evidence
cd stock-evidence
curl -fL --max-time 120 -o mtd3.bin.gz \
  https://raw.githubusercontent.com/rayniel/hm2004-fttr-research/814878f473ea499a674a6d63ca675b0f3b3e4dc9/artifacts/original/1c94686f5178/mtd3.bin.gz
gzip -dk mtd3.bin.gz
unsquashfs -processors 2 -no-progress -d rootfs mtd3.bin \
  usr/bin/moltdbg usr/bin/ploam lib/libminiolt.so
sha256sum rootfs/usr/bin/moltdbg rootfs/usr/bin/ploam rootfs/lib/libminiolt.so
llvm-objdump -d --no-show-raw-insn rootfs/usr/bin/ploam > ploam.dis
```

预期 SHA-256（若不同，先查版本/提取路径，不能继续假定地址一致）：

| 文件 | SHA-256 |
| --- | --- |
| `usr/bin/moltdbg` | `b8036696b34d35f9aee68285f4b7f7b55d7f332a2e8e0b22059637db659ab2da` |
| `usr/bin/ploam` | `feb21c78a315795ec33ed541d1e618ee114f4d1710bca28e6e0ef7b5dc7df529` |
| `lib/libminiolt.so` | `124ca148d4547025f2136753774f8fe38952c4c9553e306ae12e280589cfd63f` |

需要 `unsquashfs`、`llvm-objdump`、`readelf`、`strings`。
只做静态分析，不在主/子猫上运行外来二进制。
`libminiolt.so` 的 `MiniOltWriteFpgaReg` 在虚拟地址 `0xc04`，
映射表虚拟地址 `0x13098`、文件偏移 `0x3098`，每项三个小端 u32，
第一项为原始地址；这些定位仅适用于表中指纹版本。
